# 反射型 XSS 检测技能

## 适用条件

- 目标有带参数的 URL（形如 `?q=abc`、`?keyword=xx`），参数值会被打印到返回的页面上
- 常见于搜索框、错误提示页、跳转提示页这类"把用户输入回显出来"的地方
- 以下情况跳过本技能：参数只做后端筛选且不回显、响应是纯 JSON 或纯静态资源

## 测试阶段

1. 收集候选参数：从 URL 查询串和页面表单的 `<input name=...>` 里取
2. 注入标记标签：把参数值换成 `<xssmark1>` 这种自定义标签，编号逐个递增方便区分参数
3. 判定：响应里出现了完整的 `<xssmark1>` 原文 → 尖括号没被转义
4. 产出：命中参数、注入的标签、标签在响应里的上下文片段

## 判定标准（什么算漏洞，什么算误报）

**算漏洞**：

- 响应里出现了完整的标记标签原文 `<xssmark1>`。尖括号原样出现，说明输出编码这一步没做，
  同一个位置换成 `<script>` 就能执行

**算误报**——以下情况一律不判漏洞：

- 响应里只出现参数值本身，不见标签。比如注入 `<xssmark1>` 只回来一个 `xssmark1`，
  说明尖括号被过滤掉了，这是安全的处理方式
- 响应里出现的是 `&lt;xssmark1&gt;`。实体编码把尖括号转掉了，同样不构成漏洞
- 参数压根没有回显（响应里既没有标签也没有参数值）。不回显就没有反射型 XSS

## 决策原则

- 注入标记标签而不是真的 `alert(1)`。只验证"转义有没有做"，不在目标环境里执行任何脚本
- 参数编号要带进标签名，多个参数一起测的时候，能一眼看出命中的是哪个参数
- 置信度：标签原文完整出现给 0.8；在响应里出现在 `<script>` 或事件属性内部给 0.9（危害更高）
- 报告里必须注明"未区分输出位置"——本技能不解析 DOM，判断不出参数落在正文还是属性里

## 失败处理

- 收集不到任何参数：返回空结果并写清原因，不要对着首页硬打
- 响应里出现 WAF 拦截特征：停掉本参数剩下的动作，把已测到的结果原样返回
- 目标返回压缩后的二进制内容：按未测试处理，不做解压再匹配
