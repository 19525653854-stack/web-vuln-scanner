# 目录遍历检测技能

## 适用条件

- 目标有语义上指向文件的参数，例如 `?file=readme.txt`、`?path=/img/logo.png`、`?template=default`
- 页面上有明显的下载、附件、预览、模板切换功能
- 以下情况跳过本技能：参数语义是分页、排序、开关这类值，跟文件路径无关

## 测试阶段

1. 收集候选参数：从 URL 查询串和页面表单里取（跟注入类技能共用同一套收集逻辑）
2. 逐个参数注入遍历序列：
   - `../../../../etc/passwd`（Linux）
   - `..\..\..\..\windows\win.ini`（Windows）
   - `....//....//....//....//etc/passwd`（绕过简单过滤的常见写法）
3. 判定：响应里出现目标系统文件的内容特征
4. 产出：命中参数、注入的 payload、读到的是哪个文件、文件内容片段

## 判定标准（什么算漏洞，什么算误报）

**算漏洞**：

- 响应里出现 `root:x:0:0` 或 `daemon:x:` —— `/etc/passwd` 的账号行被读出来了
- 响应里出现 `[fonts]` 或 `for 16-bit app support` —— Windows 的 win.ini 被读出来了

这几串只会出现在系统文件里，普通网页不可能带着它们，所以命中即证据。

**算误报**——以下情况一律不判漏洞：

- 响应里只是回显了 payload 本身（把 `../../etc/passwd` 原样打印出来），没有文件内容
- 响应长度变了但没有文件内容特征。长度变化的原因太多了，不能当证据
- 命中 WAF 拦截页或统一个 404 兜底页

## 决策原则

- 一个参数命中就停手，不再试剩下的 payload，也避免连续请求触发拦截
- 只做基础遍历序列。编码绕过（`%2e%2e`、双写、超长 UTF-8）V1.0 不做，堆变形规则会让判定边界变模糊
- 置信度：读到 `/etc/passwd` 账号行给 0.9；读到 win.ini 给 0.9；只捞到片段给 0.6

## 失败处理

- 收集不到任何参数：返回空结果并写清原因，不对首页硬打
- 目标返回二进制内容：按未测试处理，不做解压再匹配
- 响应里出现 WAF 拦截特征：停掉后续请求，把已测到的结果原样返回

## 使用示例

一次真实扫描中本技能的轨迹（目标为故意有漏洞的靶场）：

1. 收集候选参数：id、q、file 三个
2. 对 file 注入 `../../../../etc/passwd`，
   响应里出现 `root:x:0:0:root:/root:/bin/bash`
3. 这串只会出现在 Linux 的 /etc/passwd 里，判定参数 file 能穿越目录
4. 对 id、q 注入同样的载荷没有出现文件内容，不判漏洞
5. 落库漏洞：类型=目录遍历　等级=high　置信度=1.0
   触发载荷：`../../../../etc/passwd`　证据：`root:x:0:0`
