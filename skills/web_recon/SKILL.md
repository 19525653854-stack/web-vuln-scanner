# Web 侦察技能

## 适用条件

- 新任务刚开始，对目标还没有任何了解
- 目标的端口分布未知，无法决定测哪些漏洞类型

## 测试阶段

1. 端口扫描：调用 port_scan 工具，探测 21 个常见端口
2. 结果分析：
   - 80 / 443 / 8080 / 8443 开放 → 走 Web 测试路线，进入下一步
   - 3306 / 5432 / 6379 / 27017 直接暴露 → 先记高危发现，数据库端口不该直接对着外面
3. 指纹识别：调用 http_probe 取首页响应，再用 fingerprint 认服务端、语言、框架、CMS
   - 认到 CMS 就走对应的专项测试（WordPress 看插件、ThinkPHP 看历史漏洞）
   - 认到 WAF 或 CDN，后续 payload 测试要放慢、要更保守
4. 产出：技术栈画像 + 缺失的安全响应头 + 建议的下一步动作

## 决策原则

- 没有任何 Web 端口（80 / 443 / 8080 / 8443）开放时，不做 Web 漏洞测试，直接缩短任务，别浪费轮次
- 数据库端口直接暴露是高危，不用等后续测试，先记录
- 端口扫描和指纹识别结果都必须写进计划快照，报告复盘要用
- 缺失的安全响应头只记录，不在这里定风险等级，等级交给反思器统一评

## 失败处理

- 全部端口不通：目标可能已下线或防火墙全开丢弃，记录后结束本轮，不重试
- 部分端口超时：按未开放处理。重试一次看不出来新东西，还拖慢整轮
- HTTP 拿不到响应：指纹识别直接跳过，端口扫描的结论照样保留，不让一个环节失败拖垮整轮
